You are helping design and build a Hiring Management System that will be a module inside an existing internal operating system called CUOS (Creative Upaay Operating System). CUOS already manages multiple internal business functions like CRM, HRMS, project management, finance, and admin operations. This new module will handle the entire hiring lifecycle for the company Creative Upaay.

The goal of this system is to automate and centralize the full recruitment pipeline, starting from job posting all the way to the final offer letter. Currently hiring workflows are fragmented and manual. Our vision is to build a structured recruitment pipeline where every candidate moves through clearly defined stages, and the internal team can manage everything from one dashboard.

The system will operate in two environments. The first environment is the internal CUOS portal (os.creativeupaay.in), which will be used by HR and hiring managers. The second environment is the public-facing application interface used by candidates.

The hiring workflow begins with job creation. Inside the CUOS admin panel, HR should be able to create multiple job positions such as Designer, Developer, HR, Sales, or Manager. Each job posting will contain information like job title, description, requirements, and hiring status. Every job will have a toggle switch that determines whether hiring is currently active for that role.

When a job toggle is turned on, that job should automatically become visible on the company's main website (creativeupaay.com). The website will show a job card containing the role name and an "Apply Now" button. Clicking this button should redirect the candidate to a public application form generated by the system.

The application form will collect candidate details such as full name, email, phone number, resume upload, portfolio link, LinkedIn profile, and other relevant information. Once submitted, the application should be stored in the CUOS database and become visible in the hiring management dashboard.

The next stage is application management. HR should be able to view all incoming applications and organize them using a tagging and pipeline system. For example, applications may be tagged as "Rejected", "Screening", "Shortlisted", or "Assignment Round". When HR applies a tag such as "Rejected", the application should automatically move to the rejected section and trigger an automated rejection email to the candidate.

For candidates who pass resume screening, the next stage is the assignment round. The system must support an assignment management module where administrators can create assignments specific to each job role. For example, a frontend developer might receive a coding challenge, while a designer might receive a design task.

Candidates will access assignments through a dedicated candidate assignment portal. This portal should display assignment instructions, a timer indicating how long the candidate has to complete the task, and a submission form where candidates can provide links such as a GitHub repository, live demo link, recorded explanation video, or other materials. There should also be a contact option in case the candidate needs clarification.

Once candidates submit their assignments, the internal team should be able to review submissions inside CUOS. HR or hiring managers can evaluate submissions, leave notes, and decide whether the candidate moves to the interview round or gets rejected.

Candidates who pass the assignment stage will move to the interview scheduling stage. The system should send them an email containing a calendar scheduling link where they can choose an available interview slot. This scheduling can be implemented using tools like cal.com or a custom scheduling interface.

When a candidate selects a time slot, the system should generate a meeting schedule (for example using Google Meet) and send confirmation emails to both the candidate and the hiring team. CUOS should also generate a notification informing the team that an interview has been scheduled.

During the interview stage, CUOS should provide an interview evaluation interface where the interviewer can record notes about the candidate. These notes may include technical performance, communication skills, strengths, weaknesses, and overall feedback. These notes should remain attached to the candidate's profile for future reference.

After the interview is completed, the hiring team will make a final decision. If the candidate is rejected, the system should automatically send a rejection email. If the candidate is accepted, the system should generate and send an offer letter along with onboarding instructions.

Overall, the vision of this hiring portal is to create a structured hiring pipeline where every stage of recruitment is organized, traceable, and automated. The system should reduce manual work, improve candidate tracking, automate communication with applicants, and integrate smoothly with the existing CUOS infrastructure.

From a technical perspective, the system will follow the same architecture as CUOS, which uses a React frontend with Redux Toolkit and RTK Query, and a Node.js + Express backend with MongoDB for data storage. Authentication, RBAC permissions, and email services already exist inside CUOS and should be reused.

The final outcome should be a fully integrated hiring management module that allows the company to manage job postings, candidate applications, assignment evaluations, interviews, and final hiring decisions from a single unified platform.
